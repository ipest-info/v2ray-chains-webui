# v2ray-chains-webui

一个部署在入口节点（例如广州）上的 Web 管理后台：通过 SSH 管理多台服务器上的 v2ray，
并把它们串成多跳线路（节点 A → 节点 B → 节点 C），每个用户一个独立账号。

单个可执行文件，页面内嵌，数据保存在一个 JSON 文件里，没有其它依赖。

## 功能

- **管理员登录**：账号密码登录（bcrypt 存储），同一 IP 连续 5 次失败锁定 10 分钟，可在页面修改账号密码。
- **节点管理**：填写 SSH 地址 / 用户 / 密码（或私钥）即可添加节点，点「安装」自动部署 v2ray（systemd 服务）。
- **SSH 跳板**：后台无法直连某个节点时，在节点的「SSH 跳板」里选择另一个能连到它的节点，
  之后对该节点的所有操作（检测 / 安装 / 同步）都会经跳板进行，支持多级。
- **线路管理**：按顺序选择入口、中转、出口节点；每一跳可以选择走上一跳到它的**内网地址**（专线）或**公网地址**。
- **用户管理**：每个用户一个 UUID，可指定可用线路、停用、重置凭据；提供 `vmess://` 链接和订阅地址。
- **节点配置项**：每个节点可单独设置日志级别、DNS、流量嗅探、是否允许访问私有地址，并可填写自定义 JSON 合并进最终配置。
- **配置备份 / 恢复**：每次同步或恢复前自动备份节点上的当前配置（保留最近 30 份），页面上可查看、恢复、手动备份。
- **出口代理**：线路末端节点之后可以再接一个 SOCKS5 / HTTP 代理作为最终出口；既可设为线路默认出口，也可单独指定给某个用户。
  支持批量导入，每行一个：`协议://用户:密码@地址:端口#名称`、`用户:密码@地址:端口`、`地址:端口:用户:密码` 或 `地址:端口`。
- **后台域名与 HTTPS 证书**：在「设置」里填写域名，用 acme.sh 一键申请证书，后台随即在 `8443` 端口提供 HTTPS，到期前自动续期。
- **带宽监控**：按用户的实时上下行速率和区间流量；各节点网卡的速率曲线（1 小时 / 24 小时 / 7 天），可按网卡查看，区分专线网卡和公网网卡。
- **日志排查**：一键检查节点的 SSH、服务状态、端口监听、配置校验、时间偏差，并解释 v2ray 日志里的常见报错。
- **安装包中转**：节点自己下载 v2ray 失败时（境内访问 GitHub 不通），自动改由其它节点下载后经 SSH 中转过去。

## 典型场景：广州 →（专线内网）→ 香港 →（公网）→ 新加坡

| 节点 | SSH 地址 | SSH 跳板 | 公网地址 | 内网地址 |
| --- | --- | --- | --- | --- |
| 广州（后台所在） | 广州内网 IP 或 `127.0.0.1` | 直连 | 广州公网 IP | 广州专线内网 IP |
| 香港 | 香港专线内网 IP | 直连 | 香港公网 IP | 香港专线内网 IP |
| 新加坡 | 新加坡公网 IP | 经「香港」跳转（广州直连不通时） | 新加坡公网 IP | 留空 |

然后添加线路：`广州` → `香港（上一跳经内网地址连接）` → `新加坡（上一跳经公网地址连接）`，端口例如 `20001`。
添加用户后点右上角「同步全部配置」，把用户页面里的链接或订阅地址导入客户端即可。

需要放行的端口（云厂商安全组；节点上的 ufw / firewalld 会在同步时自动放行）：

- 广州：线路端口，对用户开放
- 香港：线路端口，对广州内网 IP 开放
- 新加坡：线路端口，对香港公网 IP 开放

## 部署

需要 Go 1.24+ 编译（或在本地交叉编译后上传）：

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o v2ray-chains-webui .
```

首次启动通过环境变量设置管理员账号（不设置密码则随机生成并打印一次）：

```bash
ADMIN_USER=admin ADMIN_PASSWORD='至少8位的强密码' ./v2ray-chains-webui -listen :8080 -data ./data
```

### Docker Compose

```bash
cp .env.example .env   # 填写 ADMIN_PASSWORD（至少 8 位）
docker compose up -d --build
```

容器使用宿主机网络（`network_mode: host`），因此可以用 `127.0.0.1` SSH 管理本机，并直接走宿主机的专线内网访问其它节点。
数据保存在 `./data`。监听地址用 `.env` 里的 `LISTEN`（HTTP，默认 `:8080`）和 `HTTPS_LISTEN`（HTTPS，默认 `:8443`）修改；境内构建较慢时设置 `GOPROXY=https://goproxy.cn,direct`。

### systemd

作为服务运行可参考 [`deploy/v2ray-chains-webui.service`](deploy/v2ray-chains-webui.service)。

| 参数 | 说明 |
| --- | --- |
| `-listen` | 监听地址，默认 `:8080` |
| `-data` | 数据目录，默认 `./data` |
| `-https-listen` | HTTPS 监听地址，默认 `:8443`，使用后台里通过 acme.sh 申请的证书；留空则不启用 |
| `-tls-cert` / `-tls-key` | 手动指定证书，此时 `-listen` 直接提供 HTTPS，不再启用 `-https-listen` |
| `-reset-admin` | 忘记密码时重置管理员账号（读取 `ADMIN_USER` / `ADMIN_PASSWORD`）后退出 |

## 域名与 HTTPS 证书（acme.sh）

1. 把域名解析到后台所在机器的公网 IP，放行 `8443` 端口。
2. 先用 `http://IP:8080` 登录，在「设置 → 后台域名与 HTTPS 证书」填写域名，选择验证方式，点「申请 / 续期证书」。
3. 成功后访问 `https://域名:8443`，无需重启。可勾选「把 HTTP 访问自动跳转到 HTTPS」。

两种验证方式：

- **HTTP 验证**：申请时后台临时监听本机 `80` 端口供证书机构访问。要求 80 端口空闲且公网可达。
- **DNS 验证**：通过 DNS 服务商 API 自动添加 TXT 记录，不需要 80 端口。填写 acme.sh 的 dnsapi 名称
  （如 `dns_ali`、`dns_dp`、`dns_cf`）和对应的凭据环境变量（如 `Ali_Key=...`、`Ali_Secret=...`，
  变量名见 [acme.sh dnsapi 文档](https://github.com/acmesh-official/acme.sh/wiki/dnsapi)）。
  **境内服务器的 80 端口对未备案域名通常不通，请用这种方式。**

说明：

- acme.sh 在首次申请时自动下载到 `data/acme/`（固定版本 3.1.1），后台所在机器需要有 `curl` 和 `openssl`（Docker 镜像已内置）。
  访问不了 GitHub 时可在页面上更换下载地址，或手动把 `acme.sh`（及 `dnsapi/dns_xxx.sh`）放进 `data/acme/`。
- 证书保存在 `data/tls/`。后台每 12 小时检查一次，剩余不足 30 天时自动续期。
- DNS API 凭据明文保存在 `data/data.json`，接口不回传。建议使用只有 DNS 解析权限的子账号密钥。

## 工作方式

- 线路在每个节点上占用同一个 TCP 端口。入口节点上是面向用户的 VMess 入站（每个用户一个 UUID）；
  中转 / 出口节点上的入站只接受该线路专用的互联凭据，再路由到下一跳或直接出网。
- 出口节点默认禁止访问私有地址段，用户无法通过代理访问节点本机或其内网（可在节点「配置项」中放开）。
- **按用户选择出口**：用户的「最终出口」可以是「跟随线路」「末端节点直连」或某个出口代理。
  同一条线路上每个在用的出口对应一个节点互联凭据：入口节点按用户选择凭据，后续节点按凭据决定下一跳或最终出口，
  因此同一条线路、同一个端口上的不同用户可以从不同出口出网。出口代理由线路的最后一个节点去连接。
- **出口代理的 UDP**：UDP 在节点之间封装在 VMess 的 TCP 连接里，线路端口只需放行 TCP。到了出口代理这一段：
  - 只有 SOCKS5 代理可能支持 UDP，HTTP 代理不能承载 UDP。
  - 「检测 UDP」会在各线路的末端节点上临时起一个 v2ray，经该代理分别用 TCP 和 UDP 向公共 DNS（8.8.8.8 / 1.1.1.1）发一次查询：
    TCP 通而 UDP 不通判为不支持；TCP 也不通则是代理本身连不上，结果为「无法判断」。
  - 出口的「UDP 处理方式」：自动（默认；检测出不支持后不再把 UDP 交给代理）、强制经代理、不经代理。
  - 代理不转发 UDP 时，由线路决定怎么办：**丢弃**（默认，不暴露节点 IP，应用一般会回落到 TCP），
    或 **改从末端节点直接出网**（UDP 应用可用，但这部分流量的出口 IP 是节点 IP 而不是代理 IP）。
  - 检测结果和处理方式的修改都要「同步全部配置」后才生效。
- **带宽监控**：后台与每个节点保持一条常驻 SSH 连接，节点每 5 秒输出一次 `/proc/net/dev` 的网卡计数，后台据此计算速率。
  统计的是整台服务器的网卡流量（不只是 v2ray）；「合计」不含 lo、docker、veth 等虚拟网卡。
  数据只保存在后台内存里（5 秒 × 1 小时、1 分钟 × 24 小时、10 分钟 × 7 天），后台重启后重新累积。
- **按用户的流量**在线路的入口节点上统计：入口节点的配置里开启了 v2ray 的统计接口（只监听本机 `127.0.0.1:10085`），
  后台每 5 秒通过 `v2ray api stats` 读取各用户的累计流量并算出速率。同一用户走多条线路、多个入口节点时合并计算。
  需要先「同步全部配置」才会开始统计；v2ray 重启后计数从零开始，后台会自动跳过这一次。
  节点「配置项」的自定义 JSON 里如果写了 `policy`，会整体覆盖统计所需的设置，需要自己保留
  `"statsUserUplink": true, "statsUserDownlink": true`。
- **日志排查**读取的是 `journalctl -u v2ray`。默认日志级别 `warning` 只记录异常；需要看到每个连接时，
  在节点「配置项」里把日志级别改为 `info` 并同步，排查完再改回来。
- **自定义 JSON 的合并规则**：`inbounds` / `outbounds` 追加在生成的配置之后；`routing.rules` 插在最前面优先匹配；
  其它顶层字段（`policy`、`dns`、`log` 等）整体覆盖。保存后可用「预览配置」查看合并结果。
- **备份**保存在节点的 `/usr/local/etc/v2ray/backups/`。恢复只替换节点上的配置文件，不会回滚后台里的线路 / 用户数据；
  恢复后节点会显示「配置待同步」，再次同步会用后台数据覆盖。
- 修改节点 / 线路 / 用户只改后台数据；节点列表出现「配置待同步」后需点「同步配置」才会下发。
  下发时先在节点上用 `v2ray test` 校验，通过后才替换并重启，失败则保留原配置。
- 节点上的文件：`/usr/local/bin/v2ray`、`/usr/local/etc/v2ray/config.json`、
  `/usr/local/share/v2ray/`、`/etc/systemd/system/v2ray.service`。
  **该配置文件由后台整体接管**，手工修改会在下次同步时被覆盖。
- 节点要求：Linux（amd64 / arm64）+ systemd；SSH 用户为 root，或拥有 sudo 权限（免密，或 sudo 密码与 SSH 密码相同）。

## 安全说明

- 后台掌握所有节点的 SSH 凭据，**务必启用 HTTPS**（按上文用 acme.sh 申请证书，或 `-tls-cert` / `-tls-key`，或放在 HTTPS 反向代理之后），
  并尽量用防火墙限制可访问后台的来源 IP。
- SSH 密码 / 私钥、出口代理密码以明文保存在 `data/data.json`（权限 0600），请保护好该文件及其备份；接口不会返回这些凭据。
- SSH 主机公钥在首次连接时记录，之后不一致会拒绝连接；服务器重装后在节点列表点「重置主机公钥」即可重新记录。
- 订阅地址 `/sub/<token>` 无需登录即可访问，等同于用户凭据；泄露后用「重置凭据」作废。
- 用户到入口节点为 VMess over TCP（无 TLS）。
