# v2ray-chains-webui

一个部署在入口节点（例如广州）上的 Web 管理后台：通过 SSH 管理多台服务器上的 v2ray，
并把它们串成多跳线路（节点 A → 节点 B → 节点 C），每个用户一个独立账号。

单个可执行文件，页面内嵌，数据保存在一个 JSON 文件里，没有其它依赖。

## 功能

- **管理员登录**：账号密码登录（bcrypt 存储），同一 IP 连续 5 次失败锁定 10 分钟，可在页面修改账号密码。
- **节点管理**：填写 SSH 地址 / 用户 / 密码（或私钥）即可添加节点，点「安装」自动部署 v2ray（systemd 服务）。
- **SSH 跳板**：后台无法直连某个节点时，在节点的「SSH 跳板」里选择另一个能连到它的节点，
  之后对该节点的所有操作（检测 / 安装 / 同步）都会经跳板进行，支持多级。
- **线路管理**：按顺序选择入口、中转、出口节点；每一跳可以选择走上一跳到它的**内网地址**（专线）或**公网地址**。
- **用户管理**：每个用户一个 UUID，可指定可用线路、停用、重置凭据；提供 `vmess://` 链接和订阅地址。
- **安装包中转**：节点自己下载 v2ray 失败时（境内访问 GitHub 不通），自动改由其它节点下载后经 SSH 中转过去。

## 典型场景：广州 →（专线内网）→ 香港 →（公网）→ 新加坡

| 节点 | SSH 地址 | SSH 跳板 | 公网地址 | 内网地址 |
| --- | --- | --- | --- | --- |
| 广州（后台所在） | 广州内网 IP 或 `127.0.0.1` | 直连 | 广州公网 IP | 广州专线内网 IP |
| 香港 | 香港专线内网 IP | 直连 | 香港公网 IP | 香港专线内网 IP |
| 新加坡 | 新加坡公网 IP | 经「香港」跳转（广州直连不通时） | 新加坡公网 IP | 留空 |

然后添加线路：`广州` → `香港（上一跳经内网地址连接）` → `新加坡（上一跳经公网地址连接）`，端口例如 `20001`。
添加用户后点右上角「同步全部配置」，把用户页面里的链接或订阅地址导入客户端即可。

需要放行的端口（云厂商安全组；节点上的 ufw / firewalld 会在同步时自动放行）：

- 广州：线路端口，对用户开放
- 香港：线路端口，对广州内网 IP 开放
- 新加坡：线路端口，对香港公网 IP 开放

## 部署

需要 Go 1.24+ 编译（或在本地交叉编译后上传）：

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o v2ray-chains-webui .
```

首次启动通过环境变量设置管理员账号（不设置密码则随机生成并打印一次）：

```bash
ADMIN_USER=admin ADMIN_PASSWORD='至少8位的强密码' ./v2ray-chains-webui -listen :8080 -data ./data
```

作为服务运行可参考 [`deploy/v2ray-chains-webui.service`](deploy/v2ray-chains-webui.service)。

| 参数 | 说明 |
| --- | --- |
| `-listen` | 监听地址，默认 `:8080` |
| `-data` | 数据目录，默认 `./data` |
| `-tls-cert` / `-tls-key` | 启用 HTTPS |
| `-reset-admin` | 忘记密码时重置管理员账号（读取 `ADMIN_USER` / `ADMIN_PASSWORD`）后退出 |

## 工作方式

- 线路在每个节点上占用同一个 TCP 端口。入口节点上是面向用户的 VMess 入站（每个用户一个 UUID）；
  中转 / 出口节点上的入站只接受该线路专用的互联凭据，再路由到下一跳或直接出网。
- 出口节点禁止访问私有地址段，用户无法通过代理访问节点本机或其内网。
- 修改节点 / 线路 / 用户只改后台数据；节点列表出现「配置待同步」后需点「同步配置」才会下发。
  下发时先在节点上用 `v2ray test` 校验，通过后才替换并重启，失败则保留原配置。
- 节点上的文件：`/usr/local/bin/v2ray`、`/usr/local/etc/v2ray/config.json`、
  `/usr/local/share/v2ray/`、`/etc/systemd/system/v2ray.service`。
  **该配置文件由后台整体接管**，手工修改会在下次同步时被覆盖。
- 节点要求：Linux（amd64 / arm64）+ systemd；SSH 用户为 root，或拥有 sudo 权限（免密，或 sudo 密码与 SSH 密码相同）。

## 安全说明

- 后台掌握所有节点的 SSH 凭据，**务必启用 HTTPS**（`-tls-cert` / `-tls-key` 或放在 HTTPS 反向代理之后），
  并尽量用防火墙限制可访问后台的来源 IP。
- SSH 密码 / 私钥以明文保存在 `data/data.json`（权限 0600），请保护好该文件及其备份；接口不会返回这些凭据。
- SSH 主机公钥在首次连接时记录，之后不一致会拒绝连接；服务器重装后在节点列表点「重置主机公钥」即可重新记录。
- 订阅地址 `/sub/<token>` 无需登录即可访问，等同于用户凭据；泄露后用「重置凭据」作废。
- 用户到入口节点为 VMess over TCP（无 TLS）。
